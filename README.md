# 节点式工厂配平编辑器

通过节点和连线搭建产线，查看物料需求、流量与供需配平结果。支持配方机器、固定原料源、产物箱、黑盒组件、方案保存、图片导出与原料扫描。

## 启动

在线使用：<https://kokobird28144.github.io/endfield-factory-planner/>。
Pages 模式将方案、组件和临时配方保存在当前浏览器，不自动跨设备同步。
清除网站数据、更换浏览器或使用无痕窗口可能导致无法找回保存内容，请定期通过“导出 → 导出完整备份”备份。

### 本地运行

安装 Python 3.9 或更高版本，在项目目录执行：

```sh
python server.py
```

浏览器打开 <http://127.0.0.1:8770/>。Windows 用户也可双击 `start.bat`。
更改端口可运行 `python server.py 9000`。按 Ctrl+C 停止服务。

运行应用无需安装第三方 Python 包或 Node.js。前端资源随仓库提供。
本地模式由 Python 提供数据接口；在线 Pages 模式使用浏览器存储。

## 使用与备份

从左侧选择配方添加机器节点，添加固定源和产物箱，拖动端口连线搭建产线。
右键机器输入端口可选择上游配方或固定源补齐生产链。

顶栏“示例”菜单提供四个带图标的方案，选择后创建独立副本：

| 方案 | 默认产出 |
| --- | --- |
| 示例-铁制零件基础产线 | 30/分铁制零件 |
| 示例-蓝铁权重分流 | 30/分铁制零件、30/分蓝铁瓶 |
| 示例-缺料优先级分配 | 30/分铁制零件、15/分蓝铁瓶 |
| 示例-双原料芽针针剂 | 6/分芽针针剂，可用于双原料扫描 |

示例副本出现在“文件 → 打开方案”中；已有画布包含内容时，打开示例前会提示保存修改。

本地模式的方案、组件与临时配方保存在运行时创建的 `data/runtime/`，不纳入版本控制。
升级前备份此目录，升级后复制到新目录即可保留个人数据。

两种模式均支持“文件 → 导入方案 JSON”和“导出 → 导出方案 JSON”。
完整备份包含所有已保存方案、组件与临时配方，不包含尚未保存的画布修改。
可在本地模式导出完整备份，再在 Pages 模式导入，或反向迁移。
导入备份会合并数据，相同 ID 的内容被覆盖；其他已保存数据保留。
Pages 导入通过单个事务完成；本地模式逐文件写入，失败时可重新导入。

## Pages 部署

仓库 Settings → Pages 的构建来源选择 GitHub Actions。
推送 `main` 后，`.github/workflows/pages.yml` 自动组装并部署静态网站。
部署构建将存储模式标记改为 `browser`，源码默认仍使用本地服务。
配方、图标、Worker 和 WASM 均随网站部署，无需单独的后端。

## 文件结构

- `server.py`：本地服务与数据接口。
- `start.bat`：Windows 启动入口。
- `web/`：网页及所需第三方资源。
- `data/recipes/`：配方库。
- `data/item_icons/`：物品图标。

## AI 生成生产流程

项目内提供 [factory-plan-json skill](.agents/skills/factory-plan-json/SKILL.md)，指导 AI 生成可通过“文件 → 导入方案 JSON”导入的产线文件，包括配方引用、零基端口、分流规则和验证步骤。
支持项目 skill 的工具可从 `.agents/skills/` 发现它；其他工具可直接读取该文件。

示例提示词：`请按照 factory-plan-json skill，生成每分钟 30 个铁制零件的生产流程 JSON，使用内置配方，设置方案名和图标，并验证可导入性。`

可下载 [完整 JSON 样例](.agents/skills/factory-plan-json/assets/example-iron-parts.json) 后导入。
